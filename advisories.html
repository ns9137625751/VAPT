Patterns we keep finding, written up once so you can check your own systems without hiring us. Nothing here identifies a client, and nothing is published before the affected parties have shipped a fix.

Six of the last twenty API engagements accepted a token minted for a different service in the same estate. The signature verified, the issuer matched, and nothing checked that the token was meant for this audience. In two cases that turned a low-privilege analytics token into a valid session on the billing service. The defaults are the problem: all three frameworks treat aud validation as opt-in, and the quickstart in each one omits it. Check that your verifier is passed an expected audience explicitly, and that it fails closed when the claim is absent.
Teams closed their open buckets, then replaced them with seven-day presigned links pasted into support tickets, Slack channels and email threads. We found roughly 11,000 live ones across four engagements, a third of them still valid and several granting write access. A presigned URL is a bearer credential: anywhere it is logged, forwarded or indexed, it is an unauthenticated grant. Cap expiry in minutes rather than days, scope to a single object and verb, and log issuance so you can revoke.
Three of five e-commerce engagements this quarter allowed a single-use discount code to be applied several times through concurrent requests. The check and the write were separated by enough milliseconds to fit ten more requests in between. The same pattern showed up in loyalty point redemption and in one refund flow. No scanner finds this, because nothing in the response looks wrong — each request is individually valid. The fix is a database-level constraint or a lock, not an application check.
Field suggestion in error messages reconstructs most of a schema in under an hour. Ask for usr and the server helpfully replies did you mean user. Combine that with a wordlist and you have the type graph, including the admin mutations nobody meant to expose. Disabling introspection raises the cost of enumeration; it is not an access control. Turn off suggestions in production, and authorise each field on the resolver rather than relying on obscurity.
The reshuffle matters less than the shift in emphasis toward supply chain and misconfiguration. We have added dependency provenance and build pipeline review to the standard web profile, and expanded configuration coverage on the cloud side. If your last report referenced the 2021 categories, the mapping is included as an appendix in every report we issue this year so your historical tracking does not break.
Pinning still helps. It does not help as much as the architecture diagrams that depend on it seem to assume. On a rooted test device with off-the-shelf tooling, the median time to intercept across nine apps this quarter was four minutes. Treat pinning as friction against bulk interception, not as a control that lets you move a secret into the client. Anything the app can decrypt, a determined analyst can too.
Forty per cent of the criticals we raised in 2025 were object references with no ownership check. It has been the top category for four years running. It survives because it is invisible in code review — the line that fetches by id looks exactly like the line that fetches by id safely. The structural fix is to make the unsafe version impossible to write: scope every query through the authenticated principal, so there is no unscoped finder to reach for in the first place.
Median distribution was 2 critical, 8 high, 15 medium and 10 low per web engagement. Broken access control led by a wide margin, followed by authentication weaknesses and injection. Five fixes would have prevented most of the criticals we saw: scope queries to the principal, validate the JWT audience, enforce authorisation at the resolver, expire presigned URLs in minutes, and put a constraint behind every single-use token.

How we publish

Everything on this page describes a class of issue, never a specific client. Where an advisory came out of an engagement, it is published only after the client has remediated and given written consent, with identifying detail removed.

For vendor issues

  • We notify the vendor privately and give 90 days before publication
  • The window extends if a fix is in progress and communication is active
  • We publish earlier only if the issue is already being exploited
  • Credit goes to whoever found it, including your team if it was yours
